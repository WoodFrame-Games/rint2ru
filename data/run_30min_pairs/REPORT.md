# Прогон 30 минут: пары «привет» + «друг», зазор ≤ 10 000 цифр

Сервер A (EPYC, 2 vCPU), 2 потока, AVX2-генерация + SIMD-фильтр по первым
байтам ('1' для «привет», '5' для «друг»), кольцо последних 8 позиций «привет».
Команда: `./pairbig 1800 10000`.

## Итог

| Метрика | Значение |
|---|---|
| Цифр | **2161.4 млрд** |
| Время | 1800 сек |
| Скорость | **1201 млн цифр/сек** |
| Вхождений «привет» | 269 (ожидание ~216, в пределах разброса) |
| Вхождений «друг» | 2 186 714 (ожидание 2.16 млн — точно) |
| Пар с зазором ≤ 10000 | **0** |

## Почему ноль — это «не повезло», а не ошибка

Математика: P(привет на позицию) = 1e-10; после привета «друг» должен начаться
в одной из 10001 позиции: 10001 × 1e-6 ≈ 0.01. Итого ~1e-12 на позицию, при
1.2 млрд цифр/сек — **1 пара за ~14 минут**, за 30 минут ожидалось **2.2 пары**.
Вероятность выпасть нулю — e^-2.2 ≈ 11%.

Контрольный тест логики: тот же бинарник с зазором 1e8 за 45 секунд нашёл
**7 пар** — значит сопоставление и кольцо позиций работают. Примеры (зазоры в
цифрах):

```
gap=1 026 083 | привет@2256805898: ...12074[1718103620]79384... | друг: ...65204{518214}87601...
gap=1 189 837 | ...
gap=3 260 124 | ...
gap=5 524 622 | ...
```

## Замечание по скорости

1201 млн цифр/сек против 1664 млн у прицельного поиска одного слова:
двойной SIMD-фильтр ('1' и '5'), кольцо позиций и логирование пар стоят ~28%.

## Что дальше

Один прогон на 30 минут даёт ~88% шанс хотя бы одной пары; на час — ~99%.
Или снизить требование по зазору нельзя — наоборот, можно поднять частоту,
увеличив поток машин/потоков.
